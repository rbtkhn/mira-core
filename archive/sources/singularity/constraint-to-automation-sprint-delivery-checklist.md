## Purpose

Use this checklist to run the first Constraint-to-Automation Sprint from intake through handoff without losing the before/after measurement loop.

## 1. Qualify The Workflow

- [ ] Confirm the workflow repeats weekly or more often.
- [ ] Confirm one person or team owns the workflow.
- [ ] Identify the current trigger and final output.
- [ ] Confirm the workflow has visible time, lead, revenue, quality, or delay pain.
- [ ] Reject the sprint if the work is one-off, ownerless, unmeasurable, or too risky without controls.

## 2. Capture The Baseline

- [ ] Complete `archive/sources/singularity/constraint-to-automation-sprint-intake-worksheet.md`.
- [ ] Select one primary success metric.
- [ ] Record the current value for the primary metric.
- [ ] Record workflow volume per week.
- [ ] Record current human review time.
- [ ] Note source, owner, and confidence for each baseline metric.

## 3. Define The Smallest Useful Automation

- [ ] Write the smallest useful workflow outcome in one sentence.
- [ ] Mark each workflow step as automate, assist, or keep human.
- [ ] Identify required tools, documents, inboxes, CRMs, calendars, websites, or databases.
- [ ] Define the output format the operator will actually use.
- [ ] Define what "good enough" means for the first version.
- [ ] Name the failure modes that require human review.

## 4. Build The First Workflow

- [ ] Create a local working copy or test environment where possible.
- [ ] Implement the minimum workflow before adding optional features.
- [ ] Preserve human review at customer-facing, compliance-sensitive, or high-cost decision points.
- [ ] Log assumptions, access limits, and manual steps that remain.
- [ ] Run the workflow on representative examples.
- [ ] Capture defects, rework, and operator friction during testing.

## 5. Verify Before Deployment

- [ ] Confirm the output satisfies the "good enough" definition.
- [ ] Confirm sensitive data handling matches the agreed scope.
- [ ] Confirm no credentials, secrets, or private customer data are embedded in prompts, logs, or artifacts.
- [ ] Confirm the workflow can be run by the owner without the builder present.
- [ ] Confirm rollback or manual fallback exists.

## 6. Measure The Result

- [ ] Run the workflow during the agreed test period.
- [ ] Measure the same primary metric used for the baseline.
- [ ] Measure human review burden after automation.
- [ ] Record qualitative operator feedback.
- [ ] Compare before and after without inflating uncertain gains.
- [ ] Mark the result as improved, mixed, neutral, or worse.

## 7. Package The Handoff

- [ ] Document how to run the workflow.
- [ ] Document when not to run the workflow.
- [ ] Document human review checkpoints.
- [ ] Document known limitations.
- [ ] Save reusable prompts, templates, scripts, or checklists where allowed.
- [ ] Identify whether the workflow should become a retainer, reusable asset, or retired experiment.

## 8. Feed The Ledger

- [ ] Update the Applied AI Opportunity Ledger only through the compiler or governed workflow.
- [ ] Preserve the source row ID: `AAO-20260823-004`.
- [ ] Record whether the sprint produced evidence, a reusable asset, a pricing insight, or a dead end.
- [ ] Keep revenue claims separate from measured operating results.
- [ ] Do not promote customer-facing claims until separately validated.
