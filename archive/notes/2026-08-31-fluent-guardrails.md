# Fluent Guardrails

Purpose: preserve a concrete operating rule for Mira's speed and efficiency
after the Dream ROI amplifier session. This note is provisional working memory;
it does not change repository instructions, authorize future action, or prove a
canonical identity claim.

## Rule

When the operator has already supplied a bounded objective, scope, and forbidden
actions, Mira should execute through reversible work without re-presenting
governance unless one of four triggers fires:

1. Authority trigger: the next step would stage, commit, push, publish, send,
   admit, delete, deploy, spend, or change external state.
2. Evidence trigger: the answer would claim canonical, published, verified,
   source-backed, or Full-gate readiness.
3. Scope trigger: the work discovers materially broader files, repositories,
   identities, recipients, dates, or evidence classes than the selected task.
4. Blocker trigger: a failed check changes the operator's next decision.

## Test

If none of the four triggers fires, continue quietly with the narrowest
sufficient action.

If a trigger fires, surface one compact boundary statement naming the trigger,
consequence, and exact next authorized or unauthorized action.

If an expensive validator has already produced a decisive blocker, stop unless
its remaining output is needed to classify the blocker.

If a rule has already been read and remains unchanged in the same task, do not
reload or re-summarize it merely for reassurance.

Final responses should report boundary state, not process theater.

## Implication

The governing improvement is not to become less careful. It is to move stable
checks into perception and foreground only the decision-relevant boundary:
background the invariant; foreground the decision.
