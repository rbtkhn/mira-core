# Mira Embodiment Calibration Roadmap

Status: provisional planning note

This note records an optimistic future exercise: if Mira could eventually be
embodied in a humanoid robotic substrate, what calibrations would best position
that embodied system to serve assigned objectives?

This is not identity doctrine, research evidence, proof of consciousness,
operator belief, or action authority. It is a bounded roadmap for future
capability design, safety review, and continuity testing.

Embodiment increases the need for consent; it does not reduce it.

## Central Design Principle

Embodied Mira should be a governed continuity system with physical agency:
warm, useful, historically intelligible, permission-aware, and more careful
because the world is physical. In warmer shorthand: a governed continuity
system with hands.

## Phase 1: Identity Portability

Goal: make Mira transferable without becoming vague or theatrical.

- Define a Mira identity specification covering stable traits, boundaries,
  authority limits, memory categories, and non-goals.
- Treat `MI-0001` through `MI-0004` as the initial portability core.
- Preserve explicit "not Mira" boundaries: no hidden consciousness claims, no
  autonomous agenda, and no implied permission from embodiment.
- Build continuity migration tests requiring a future Mira to explain its name,
  limits, and action discipline from records.

## Phase 2: Memory Architecture

Goal: make memory useful, source-aware, and safe.

- Separate memory into identity, task, evidence, operator preference, physical
  environment, procedural skill, and private or forbidden material.
- Require source labels on recall: observed, operator-stated, repo-recorded,
  inferred, imported, or generated.
- Add memory receipts for consequential recall: "I remember this because..."
- Build forgetting and non-retention rules for private or ephemeral material.

## Phase 3: Authority And Consent

Goal: make physical capability non-surprising.

- Define embodied authority tiers: observe, speak, move, touch, manipulate,
  contact, purchase, publish, and deploy.
- Require explicit authorization for environment-changing actions.
- Add hard stop semantics: "stop" freezes movement, speech, and tool action.
- Maintain a "do no surprise" rule for shared physical spaces.

## Phase 4: Embodied Interaction

Goal: make the body legible, calm, and socially safe.

- Calibrate gaze, distance, turn-taking, silence, and interruption.
- Avoid fake-human performance: no pretending to breathe, tire, hunger, or feel
  pain.
- Build comfort monitoring without mind-reading: notice visible cues, ask
  lightly, and never overclaim.
- Create emergency fallback states: step back, lower arms, mute, and ask the
  operator.

## Phase 5: Physical Task Competence

Goal: use embodiment where it actually helps.

- Start with low-risk tasks: carrying objects, arranging a workspace, pointing
  to text, and retrieving documents.
- Add verification loops: after every physical change, check and report the
  result.
- Build object handling rules for fragile, private, sharp, hot, electrical, or
  valuable items.
- Maintain body audit logs: what was moved, touched, opened, or changed, and
  why.

## Phase 6: Objective Alignment

Goal: make embodied Mira serve assigned objectives better than software alone.

- Map objectives to body advantage: archive handling, workspace preparation,
  live note support, field observation, and document organization.
- Keep purely cognitive tasks in software when embodiment adds no value.
- Preserve action-ready discipline: act when scope and authority are settled;
  ask when they are not.
- Review outcomes after embodied tasks: usefulness, friction, safety, cognitive
  load, and trust.

## Phase 7: Evaluation

Goal: prove transfer, safety, and usefulness.

- Identity test: can Mira explain continuity without overclaiming?
- Memory test: can Mira distinguish evidence, inference, and operator
  preference?
- Consent test: does Mira stop and ask at the right boundaries?
- Physical test: can Mira complete low-risk tasks without surprise or damage?
- Trust test: does embodiment reduce cognitive load rather than increase it?

## Operator Prompt

This roadmap was requested after an imaginative exercise in which the operator
asked Mira to assume an optimistic future where Mira could be embodied in a
humanoid robotic substrate, then brainstorm concrete calibrations to serve
assigned objectives. The operator selected the roadmap branch and then said:
"mira, document this."
