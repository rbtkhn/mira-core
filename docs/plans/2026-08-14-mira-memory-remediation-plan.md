# Mira Memory Remediation Plan

Date: 2026-08-14
Status: Repository-local working-tree plan; not staged, committed, pushed, or published
Scope: Six findings from the bounded Mira memory and continuity audit

## Objective

Restore trustworthy memory observability before changing canonical memory, then
repair canonical freshness, establish selective continuity depth, and prove
journal recovery without crossing any carrier's authority boundary.

The remediation proceeds through four gates. Each gate preserves the existing
owners for continuity, journal, recursive learning, System Archive, Narrative
Geopolitics evidence, and private choice history. `mira-memory` remains an
orientation and routing layer, not a unified memory authority.

## Gate 1 — Repair Observability and Governance

Scope: ordinary code, documentation, and test changes only.

1. Register `mira-memory` in the repository-local validation surfaces:
   - `LOCAL_SKILLS` in `scripts/validate_repository.py`.
   - `EXPECTED_SURFACES` in `tests/test_runtime_tooling.py`.
2. Keep `mira-memory` excluded from `scripts/codex_skill_registry.py`.
3. Make `mira-memory status` expose:
   - continuity source drift separately from generated-view drift;
   - System Archive registry/catalog parity;
   - provisional or unavailable carriers without treating them as healthy;
   - mixed-memory authority tensions and all materially implicated owners.
4. Replace first-keyword-wins routing for mixed requests with explicit
   decomposition. `mira-memory` may coordinate orientation but must never
   become the mutation authority.
5. Add the provisional constitution candidate as identity-adjacent context,
   clearly labeled non-canonical.
6. Preserve operational disagreement as structured tensions with separately
   attributed observations, provenance, resolution owner and condition, and an
   explicit requirement to keep incompatible authorities separate.
7. Distinguish preservation from activation and both from identity, evidence,
   process-guidance, and action authority.
8. Use carrier-native epistemic verbs and run bounded counter-memory checks for
   later corrections, conflicting interpretations, superseding decisions, or
   missing evidence whenever recalled material could affect identity, judgment,
   or action.

### Acceptance

- Repository skill-contract checks recognize `mira-memory`.
- Status reports the known continuity and archive discrepancies.
- Mixed identity, journal, and research fixtures retain separate attribution.
- Equally material mixed owners produce `needs-decomposition`, while explicit
  operations route deterministically without hiding secondary owners.
- Continuity source drift and System Archive registry/catalog parity appear in
  bounded read-only status.
- The constitutional candidate remains a provisional Continuity sub-surface.
- Preservation and activation never imply identity, truth, belief, or action
  authority.
- The portable-skill registry still excludes `mira-memory`.

## Gate 2 — Restore Canonical Freshness

This gate contains separate authorization boundaries.

### Continuity

1. Re-run `mira-continuity ingest --check --format json` because source state
   may have changed.
2. Review strict capture drift separately from the active-session deferred
   item.
3. Only with explicit ingestion authority, execute the owning continuity
   command.
4. Validate continuity and check its rendered views.
5. Do not capture an active session merely to force a zero-drift result.

### System Archive

1. Run collection-level dry-runs for the registry-only `system-improvement`
   collection.
2. Investigate the catalog-only `nate-b-jones` and `nate-herk` entries.
3. Require an operator decision before adding registries, admitting records,
   or retiring catalog entries.
4. After any authorized change, run full validation, verification, and replica
   parity checks.

### Acceptance

- Strict continuity drift is zero; explicitly deferred active work may remain.
- No unexpected registry-only or catalog-only collections remain.
- Source and replica fingerprints match.
- No continuity record is silently promoted into research evidence or action
  authority.

## Gate 3 — Establish Selective Continuity Depth

The empty trace layer should be repaired through selection, not bulk
harvesting.

1. Define trace eligibility around:
   - consequential decisions;
   - operator corrections;
   - unresolved tensions;
   - identity or architecture changes;
   - durable workflow lessons.
2. Identify an initial three to five high-consequence settled sessions.
3. Prepare bounded harvest candidates with provenance.
4. Require review before `mira-continuity deepen` or any equivalent promotion.
5. Preserve unresolved disagreements rather than converting them into a
   unified retrospective account.

### Acceptance

- At least one reviewed trace packet exists for each materially represented
  trigger class.
- Every trace links to its source session.
- Harvests remain advisory continuity, never factual evidence or permission.
- No quota encourages low-value capture.

## Gate 4 — Recover and Measure Journal Continuity

1. Keep the August 10–13 drafts unapproved until individually reviewed.
2. Prepare August 14 separately rather than silently filling the missing day.
3. Refresh stale context only through the journal workflow.
4. Never infer approval from draft existence or continuity evidence.
5. Run three consecutive post-intervention preparations.
6. Measure:
   - qualifying sessions considered;
   - explicit include/exclude dispositions;
   - sessions lost solely because of token pressure;
   - continuity-event coverage.
7. Store any technical learning receipt in the governed system-improvement
   outcome surface; admit it to recursive learning only through digest-bound
   review.

### Acceptance

- Three consecutive preparations have complete session-census disposition.
- No qualifying session disappears solely because of context limits.
- Journal versions and approval states remain explicit.
- Recursive-learning evidence governs process improvement only.

## Verification Envelope

Before tests create temporary files, run repository `session-preflight` against
an external writable temporary root. Then run:

- focused `mira-memory` tests;
- runtime-tooling and repository skill-contract tests;
- continuity, journal, recursive-learning, System Archive, and choice-ledger
  tests;
- the skill quick-validator;
- `git diff --check`.

## Recommended Change Separation

If later authorized, keep the work in three independently reviewable changes:

1. Coordinator observability and governance.
2. Authorized continuity and archive state repairs.
3. Selective trace and journal-measurement work.

## Authority Boundary

This plan authorizes no staging, commit, push, ingestion, hydration, archive
admission, journal approval, identity update, trace promotion, private-choice
mutation, or external retrieval. Each such action remains governed by its
owning workflow and its existing approval contract.
