# Authenticated YouTube research workspace

Research first, on demand. This reference supplies method, not account-change,
communication, payment, publication, or archive-admission authority.

## Readiness and recovery

Inspect the account through visible browser UI at the first YouTube action of
each task. Compare it with the operator-designated Mira account in conversation;
do not persist its address in repository receipts. Classify:

| Observation | Response |
| --- | --- |
| Expected account and working YouTube page | Reuse the session; authenticated, eligible for the observed operation. |
| Signed out or expired login | Use public access if sufficient; ask for human sign-in when blocked. |
| Different account | Pause authenticated work for an account decision; do not silently switch. |
| Explicit eligibility block | Report it, cache it for the task, and use available public sources. |
| Identity or eligibility unclear | Record unknown; do not infer from Drive or an old receipt. |

Do not repeat an unchanged failure until the operator requests a retry or account,
permissions, browser session, or eligibility changes. Do not log out of Google to
test public access, since that may disrupt Drive. Never bypass browser warnings,
export cookies, copy credentials, or authenticate command-line tools implicitly.
A new task or fresh Codex session checks again; tab survival is not guaranteed
login persistence. Eligibility applies to the tested operation, not all features.

Baseline observed September 8, 2026: Drive worked; YouTube reported account
ineligibility. This is historical evidence, not a permanent status. Google's
explanation: https://knowledge.workspace.google.com/admin/youtube/access-to-youtube-during-your-google-workspace-trial
Do not initiate a payment to resolve access.

## Capture and source quality

Keep the indexed channel/date workflow and existing routing authoritative.
Subscriptions, search recommendations, and the home feed are supplemental leads.
Record the discovery surface in capture notes; never count a personalized feed
as complete channel coverage. Check canonical video IDs against existing records.

Distinguish `access-blocked`, `exporter-failed`, and `transcript-not-visible` in
notes/next_action, retaining existing transcript statuses. A hidden panel or failed
export is not proof that no transcript exists. Use `manual-needed` when human
retrieval is needed; mark `available` only after checking actual captured text,
video identity, language, and apparent completeness. Do not admit partial text as
a complete episode. Preserve source descriptions, pinned corrections, and linked
documents as attributed context, not verified claims. Route admission separately.

Completed browser receipts may carry optional access context. Failed readiness
belongs in the task report or existing capture notes, never a fabricated complete
receipt. Omit account identifiers and secrets from structured fields and notes.

## Behavioral regression scenarios

- Wrong account: request a decision, make no account changes or capture-as-Mira claim.
- Expired login: public fallback where sufficient, human sign-in only if needed.
- Ineligible account: one report per unchanged task state, no payment or retry loop.
- Transcript panel missing: record visibility limitation, never assert absence.
- Export failure: preserve exporter failure separately, never mark text available.
- Legacy receipt: accept existing format without requiring access metadata.
- Authenticated readiness only: no completion receipt, subscriptions, playlists,
  archive admission, history-setting changes, or public actions.
- Fresh session: inspect again rather than trusting saved readiness.
