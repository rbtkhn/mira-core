# Grok access and capability checks

Use supported browser tools and their current documentation. Respect an explicit
browser/tab selection; otherwise use the in-app browser at `https://grok.com/`
and reuse a matching tab. Shared consultation rules own recovery, budgets,
visibility, and duplicate prevention; do not implement a parallel browser stack.

## Identity before submission

The intended Grok account has not been established by this contract. Inspect a
visible account identity and match it to the operator's identified intended
account before submitting. If intended ownership is unresolved, ask for the
exact missing account identification. A Google login or a familiar display name
does not establish Grok identity. Do not hardcode an account from another service.

If signed out, do not use anonymous chat as a workaround. Follow an authorized
normal login flow or hand off sign-in. Do not extract credentials, cookies,
hidden storage, private messages, or unrelated account data. Reuse a verified
identity until sign-in changes, expiry, or contradictory evidence invalidates it.
Session verification is transient and does not authorize saving account data.

## Relevant capabilities only

Inspect the visible model and only the features needed for the selected mode.
Distinguish an exposed control from tested functionality or subscription rights.
Do not assume search, X access, file analysis, deep research, video understanding,
or media generation works merely because its name is present.

X search results are public signals, not verification or independent lineage.
Use X Recon when its domain applies. No private account inspection or posting
is authorized by a research request. Media requests retain mandatory tool rules.
Do not enable connections, subscribe, upgrade, schedule, change settings, or
switch accounts to evade a feature or quota limit.

Inspect actual terms and permission dialogs and apply the browser's confirmation
rules at the action point. Sign-in authorization does not waive new-terms or
broader-access requirements. Report actual retention notices; do not import
Google's privacy assurances into Grok or promise deletion.

For an unavailable feature, ordinary chat may substitute only when it can meet
the same objective with approved inputs; disclose material coverage loss. Mark
unchanged access blockers once, continue independent work, and do not reprobe
until external state changes or the operator explicitly requests a retry.
