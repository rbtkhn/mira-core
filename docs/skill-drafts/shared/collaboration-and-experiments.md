# Consultation, critique, synthesis, and experiments

Read for consult, critique, synthesize, or experiment. Add the evidence reference
when conclusions depend on external factual claims.

## Consultation and critique

Name the decision, audience, constraints, and expected contribution. Use an
independent first answer when anchoring would obscure a second perspective;
provide the existing argument when testing that argument is the purpose.
Do not conceal task constraints merely to make an answer seem independent.

For critique, give the approved artifact or excerpt and the intended standard.
Ask for concrete defects with consequences and repair suggestions, prioritizing
substantive errors over cosmetic preferences. Request location references when
the input supports them. Criticism should preserve the author's purpose and
material qualifications, not replace them with the provider's preferred assignment.

Mira assesses each important suggestion before adopting it. Distinguish an actual
defect from a taste preference, unsupported assertion, or scope expansion. Do not
edit an artifact solely because critique was requested; preserve the task's
existing edit authority. Do not load unrelated private files to improve a prompt.

## Candidate synthesis

Provide an explicit approved input set. Ask the provider to associate material claims
with those inputs, preserve contradictions and uncertainty, and label its own
interpretation. Do not let polished prose convert inference into observation or
erase disagreements among authors. Clearly label any permitted outside research.

Review coverage, attribution, chronology, and unsupported connections. The provider's
draft is a candidate; Mira recomposes the final response under Mira Voice and
the applicable artifact workflow. Saving, source admission, Library relationships,
and publication remain separate from composing a response.

## Matched experiments

Before generating either answer, define the question, common approved inputs,
output constraints, assessment criteria, and effort ceiling. Keep Mira's baseline
in conversation without sending it to the provider for an independent comparison.
If a prior answer is the baseline, disclose its different conditions rather than
pretending it was collected under a preregistered protocol.

Use task-relevant criteria such as correctness against accessible sources,
attribution, coverage, causal discrimination, actionable improvements, and effort.
Do not reduce these to an invented numerical score. Capture visible model labels
and unequal tools or source access as confounders. Never claim blindness when
the evaluator knows which model produced each response.

For a requested quantitative benchmark, report directly interpretable counts:
cases completed, explicit requirements met, substantive errors with named
examples, submissions, corrective rounds, and response length. Define the word
count convention and distinguish a requested length target from a hard cap.
Report time from dispatch to observed completion as observation latency, not
pure generation speed. Declare when scoring rules were set after a run began;
do not describe such a comparison as preregistered. Keep original-response
compliance separate from the locally corrected final result.

Compare the original outputs before sharing critiques. If a follow-up is used,
label the revised result separately; do not replace the first result silently.
Do not add another model, delegate to subagents, change account settings, or
expand the prompt budget without applicable authority.

A single trial establishes only that task's observed contribution. It does not
establish general model superiority, reliable research performance, or recursive
learning. Report a win, mixed result, failure, or no added value with concrete
reasons. Routine consultations can note usefulness without becoming experiments
or opening a performance ledger.

## Completion

Return the accepted contribution and Mira's assessment, rejected suggestions,
unresolved questions, and the entrypoint's compact receipt. Do not manufacture
another round after the work is done. Link the account conversation when useful,
without using a public-share action. Local storage remains opt-in and governed
by the intended artifact's workflow.
