# Kremlin Sourcing

Use this module only for material attributed to the President of Russia,
presidential administration, or signed presidential acts. It optimizes actor-
position verification; it does not make an interested source independent.

## Admission gate

1. Check `narrative-geopolitics/work/reality/sources/` for the active source
   `VSRC-OFF-KREMLIN`.
2. If absent, treat Kremlin pages as leads. Source admission is separate from
   investigation authority.
3. Admit the source only after explicit operator authorization. The lattice
   has no source-admission CLI; follow the canonical source-record conventions
   under `work/reality/sources/`, record interested-source limitations, and
   validate the new source record before collecting evidence.
4. Never use source admission to authorize an assessment, publication,
   forecast scoring, or downstream prose revision.

## Retrieval order

Prefer one attributable event record in this order:

1. Russian original at `kremlin.ru/events/` or `kremlin.ru/acts/`.
2. Exact `special.kremlin.ru` mirror when the ordinary page is inaccessible.
3. Official English edition at `en.kremlin.ru` as an access edition.
4. A separately registered official legal-publication source for enacted law.
5. TASS or another state outlet only as a lead or reproduction.

Do not substitute a site index, search-result snippet, press summary, or
commentator paraphrase when the event transcript is retrievable.

Search Russian originals first. Start with the exact actor, object, and policy
verb, then widen conservatively. Useful policy distinctions include:

- `Одесса`, `Новороссия`, `русский город`;
- `условия переговоров`, `мирное урегулирование`;
- `прекращение огня`, `вывод войск`;
- `цели специальной военной операции`;
- `принятие в Российскую Федерацию`, `воссоединение`.

Bound every search by the claim window. Record material search failures when
they constrain the conclusion; absence from search results is never evidence
by itself.

## One event, one lineage

Assign one stable originating-chain root to the underlying presidential event
or signed act. Reuse it across:

- Russian and English editions;
- ordinary and special-access mirrors;
- transcript, video, quotation, and press-summary forms;
- TASS and other syndications of the same event.

Translations, mirrors, quotations, and syndications never add lineage
independence. A later speech or a distinct signed act may be a new event
lineage, but it remains within the same interested geopolitical environment.

## Policy hierarchy

Classify what the record can establish before choosing a relation:

1. enacted law, signed treaty, decree, or annexation instrument;
2. formal settlement proposal or enumerated negotiation condition;
3. direct presidential statement of current policy or intent;
4. historical, civilizational, or identity attribution;
5. aide, spokesperson, or state-media characterization.

Do not silently promote identity rhetoric into a territorial requirement,
declared intent into capability, a proposal into an agreement, or a signed act
into successful implementation.

## Relation discipline

- Use `supports` only when the record directly supports the bounded claim.
- Use `challenges` for an explicit contrary position or a genuinely bounded
  conflict with an exhaustive formal policy statement.
- Use `contextualizes` when rhetoric establishes identity, history, motive, or
  background without resolving the operative claim.

Omission is not renunciation. An omitted object in an expressly enumerated,
purportedly sufficient settlement package may challenge indispensability, but
state the package's date, conditionality, and susceptibility to later change.
Failure to find a demand is `unavailable`, not a zero and not a contradiction.

## Evidence capture

For every admitted observation, preserve:

- exact event URL, title, and event time;
- origin and access languages;
- official or machine-assisted translation provenance;
- stable originating-chain root;
- the smallest sufficient observation;
- interested-source, scope, and implementation limitations.

Validate each evidence and relation record before continuing. End the search
when a binding answer is found, a meaningful supporting and challenging pair
is established, or the declared evidence threshold remains honestly unmet.
