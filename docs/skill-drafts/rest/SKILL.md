# Rest

Use only in `mira-core`. Rest is session-scale: Dream is day-scale and Coffee
is re-entry-scale. Rest never invokes or mentions either workflow in its
terminal response.

## Close

1. Resolve the private Continuity inbox at the canonical portable path
   `.mira-private/sessions/rest/`. Accept `MIRA_CORE_CONTINUITY_INBOX` or an
   exact operator-supplied absolute path only as a warning compatibility
   override; fail closed when it conflicts with populated canonical state.
2. Run `tools/run.ps1 rest --check --json` and inspect bounded closure debt.
3. Run `tools/run.ps1 rest --json` once. Resume a returned live process rather
   than launching another.
4. Report receipt retention and each material debt class once, then stop. Do
   not produce a handoff, possibility menu, or invitation to continue.

Bare Rest authorizes only the private receipt. If storage is unavailable,
close conversationally and disclose that the receipt and review requests were
not retained.

## Preserve reopening

`rested` means no return is presently expected, not prohibited. Later operator
activity resumes work normally and performs no Rest mutation. A subsequent
explicit Rest records the intervening resume and new rest atomically. Duplicate
adjacent lifecycle states are idempotent.

## Memory and learning boundaries

- The inbox is a private provisional Continuity sub-surface, not canonical
  identity or a new carrier.
- Journal review is pending consideration only. Rest drafts and approves no
  prose.
- Recursive Learning review is pending screening only. A Rest receipt,
  Journal interpretation, review request, or passing test supplies none of the
  five learning stages.
- Existing files and open choices remain preserved. Rest does not infer
  abandonment, success, operator belief, evidence, or permission.

## Boundary

Rest performs no Continuity ingestion, Dream close, Coffee action, Journal
approval, recursive-learning assessment or admission, choice resolution, Git
mutation, publication, task archival, deletion, or external communication.
