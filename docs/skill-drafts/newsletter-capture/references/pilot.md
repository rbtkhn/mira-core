# Supervised pilot

Use an external preflighted temporary root for synthetic tests. Run focused
newsletter and Tower tests before live admission. Do not enable the pilot flag
from synthetic evidence.

Inspect real original/extraction pairs for each route being enabled. Confirm
headings, paragraph boundaries, hyperlinks, attribution, complete ending, and
source/receipt dates. Review dry-run metadata before live landing. Check the
source body, manifest membership, author routing, and unintended index changes.

Exercise complete article, welcome message, promotional message, paid preview,
video notice, exact duplicate, and changed article fixtures. Repeat capture and
intake; simulate interruptions after original preservation and after landing.
Missing access must be a coverage gap and must not mark the inbox empty.

Conduct one real Tower inquiry with a landed newsletter. Inspect the prior
assessment and corrections first; record source-bound judgment, strongest rival,
uncertainty and return point. Preserve shared source ancestry when newsletters
repeat one report. Missing correction coverage limits the claim. An operator's
new question governs over the previous recorded inquiry.

Capture-only execution must not retrieve unrelated memory or write Journal,
Notes, Continuity, or RSI records. Keep Library's existing bounded route; record
effect, no change, or explicit deferral through its owner.

Only after these checks pass, run accept-pilot with the actual substantive
Tower contribution. The command verifies a considered newsletter's exact version.
Any new publication route invalidates routine activation and requires renewed
review. Scheduling and wider backfill remain out of scope.
